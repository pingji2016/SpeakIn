## 1. 背景与目标

### 1.1 当前问题

SpeakIn 目前的语音识别是**录完再识别**（Record-Then-Transcribe）模式：

```
用户按下录音 → AudioRecord 持续写 PCM 到文件
       ↓
用户按下停止 → 封装成 WAV 文件 → 整个文件送 ASR 引擎
       ↓
等待 3~10 秒 → 转写结果显示
```

**痛点**：
- 用户录音结束后需要**等待数秒**才能看到转写结果，体验割裂
- 录音过程中完全不知道转写质量（环境太吵？麦克风被挡？只能事后发现）
- 长录音的等待时间更长，焦虑感随录音时长递增
- 模型文件（Whisper .pte ~180MB）打包在 APK 中，安装包体积过大

### 1.2 改造目标

实现**边录边识别**（Streaming ASR），达到以下效果：

| 指标 | 当前 | 目标 |
|------|------|------|
| 首次结果可见 | 录音结束 + 3~10s | 录音开始后 3~5s |
| 结果更新频率 | 仅一次 | 每 2~3s 刷新 |
| 录音结束后等待 | 3~10s（完整推理） | ~1s（仅增量推理） |
| 前向纠错 | 不支持 | 结果渐近稳定，变化部分高亮提示 |
| 用户体验 | "黑盒等待" | "所见即所得，渐近收敛" |
| APK 体积 | ~180MB（含模型） | 模型按需下载，APK < 20MB |

### 1.3 非目标

- 不做**逐字实时**级别的流式识别（需要替换为流式模型，如 SenseVoice / Paraformer）
- 不改变模型本身（继续使用 Whisper tiny）
- 不改变录音格式（16kHz / 16-bit / 单声道 PCM）

### 2.2 核心瓶颈

#### 瓶颈 1：AudioRecorder 不暴露中间数据

```kotlin
// AudioRecorder.kt — 当前实现
private fun writePcmData(outputFile: File, bufferSize: Int) {
    val buffer = ShortArray(bufferSize / 2)
    while (_isRecording) {
        val bytesRead = audioRecord?.read(buffer, 0, buffer.size) ?: -1
        if (bytesRead > 0) {
            // ShortArray → ByteArray → 写入文件
            // ← 这里没有把数据回调出去！
        }
    }
}
```

录音数据只写入文件，外部完全无法获取音频流。

#### 瓶颈 2：AsrEngine 接口只接受完整文件

```kotlin
// AsrEngine.kt — 当前接口
interface AsrEngine {
    fun transcribe(audioFile: File, callback: Callback)  // ← 只接受文件
}
```

没有流式输入的 API。

#### 瓶颈 3：ExecuTorchWhisperEngine 以整个 FloatArray 为单位

```kotlin
// ExecuTorchWhisperEngine.kt — 当前实现
fun transcribe(audioPcm: FloatArray, onProgress: ((Float) -> Unit)? = null): String? {
    val audioInput = if (audioPcm.size >= N_SAMPLES) audioPcm.copyOf(N_SAMPLES)
                     else FloatArray(N_SAMPLES).also { ... }  // 填充到 480000
    // Encoder → Decoder 自回归 → 返回完整文本
}
```

每次转写都是独立的、无状态的完整推理。

#### 瓶颈 4：AIDL 接口基于文件路径

```java
// IModelService.aidl
void transcribe(String audioPath, IModelServiceCallback callback);
```

音频通过文件路径传递，不适用于内存中的数据块。

#### 瓶颈 5：模型内置在 APK 中

当前通过 `AsrModelManager.prepareFromAssets()` 从 APK assets 复制模型文件到内部存储。这导致：
- APK 体积膨胀（Whisper tiny 三文件约 180MB）
- 每次更新模型都需要发新版 APK
- 用户可能不需要 ASR 功能，却被强制下载大 APK

## 3. 流式识别整体方案

### 3.1 方案选择

针对 Whisper 模型的特性（Encoder-Decoder 架构，30 秒输入窗口），我们采用 **"周期增量识别 + 渐进式结果纠错"** 策略：

```
录音过程中，每累积 N 秒新音频 → 触发一次增量识别 → 对比上次结果，UI 渐进更新
```

这与真正的"逐帧流式"不同，但能在**不换模型**的前提下大幅改善体验。

#### 为什么不用真正的流式模型？

| 方案 | 优势 | 劣势 |
|------|------|------|
| **周期增量识别**（本方案） | 不换模型，改动可控，快速上线 | 有 2~3s 延迟，非逐字实时 |
| 替换为流式模型（SenseVoice 等） | 真正的实时，延迟 < 500ms | 需要新模型导出/集成/测试，周期长 |
| 使用 Android SpeechRecognizer | 系统内置，零模型体积 | 需联网，不可控，与"全离线"定位冲突 |

**选型结论**：先用周期增量识别快速上线改善体验，架构上预留流式模型接入点。

### 3.2 核心设计思路

```
录音开始
   │
   ▼
AudioRecorder 开始采集 ──→ 每 200ms 产生一个音频块 (FloatArray, 3200 samples)
   │                              │
   │                              ▼
   │                      AudioBuffer 累积
   │                              │
   │                    每 ~2s 触发一次识别
   │                              │
   │                              ▼
   │               ExecuTorchWhisperEngine
   │               对累积音频做完整推理
   │               (不足 30s 则补零)
   │                              │
   │                              ▼
   │               渐进式结果纠错（对比上次结果）
   │               ├─ 稳定前缀：保持不变
   │               └─ 变化后缀：高亮动画显示
   │                              │
   │                              ▼
   │               UI 更新 liveCaption（带稳定/变化标记）
   │                              │
   │                     (继续累积，继续识别)
   │                              │
   ▼                              │
录音停止 ─────────────────────────┘
   │
   ▼
最后一次完整识别 → 渐进收敛 → UI 显示最终结果
```

Whisper 在音频不足时可能产生错误，随着更多音频到达会自动修正：

```

              UI: "金色" 替换为 "今天天气"，变化部分闪烁提示
识别#3 (4s):   "今天天气很好"   ← 前缀匹配，追加新内容
```

### 4.2 音频采集层改造

#### 4.2.1 AudioChunkListener — 音频块回调

```kotlin
// domain/audio/AudioRecorder.kt

class AudioRecorder {
    // 新增：音频块监听器
    interface AudioChunkListener {
        /**
         * 当有新音频数据可用时回调。
         * @param chunk PCM 数据，16kHz 16-bit 单声道，归一化到 [-1.0, 1.0]
         * @param timestampMs 自录音开始以来的时间戳
         */
        fun onAudioChunk(chunk: FloatArray, timestampMs: Long)
    }

    private var chunkListener: AudioChunkListener? = null

    fun setChunkListener(listener: AudioChunkListener?) {
        this.chunkListener = listener
    }

    // 修改 writePcmData 方法
    private fun writePcmData(outputFile: File, bufferSize: Int) {
        val buffer = ShortArray(bufferSize / 2)
        var totalSamples = 0L

        while (_isRecording) {
            val bytesRead = audioRecord?.read(buffer, 0, buffer.size) ?: -1
            if (bytesRead > 0) {
                // 1. 写入文件（保留原有逻辑，用于最终完整转写和回退）
                writeToFile(buffer, bytesRead, fileOutputStream)

                // 2. 转换为 FloatArray 并回调（新增）
                val floatChunk = FloatArray(bytesRead) { i ->
                    buffer[i].toFloat() / 32768f
                }
                totalSamples += bytesRead
                val timestampMs = totalSamples * 1000L / SAMPLE_RATE
                chunkListener?.onAudioChunk(floatChunk, timestampMs)
            }
        }
    }
}
```

#### 4.2.2 AudioBuffer — 音频累积器

```kotlin
// domain/audio/AudioBuffer.kt (新文件)

/**
 * 线程安全的音频数据累积器。
 * 用于流式识别场景：持续收集音频块，按需提供完整的 PCM 数组。
 */
class AudioBuffer(private val maxDurationSamples: Int = 480000) { // 默认 30s

    private val lock = Any()
    private val buffer = ArrayList<Float>()

    val durationMs: Long
        get() = synchronized(lock) { buffer.size * 1000L / 16000L }

    val sampleCount: Int
        get() = synchronized(lock) { buffer.size }

    /** 追加一个音频块 */
    fun append(chunk: FloatArray) {
        synchronized(lock) {
            for (sample in chunk) buffer.add(sample)
            // 超过最大长度时，保留最新的 N 个样本（滑窗）
            if (buffer.size > maxDurationSamples) {
                val excess = buffer.size - maxDurationSamples
                buffer.subList(0, excess).clear()
            }
        }
    }

    /** 获取当前累积的完整音频（不足 480000 时补零） */
    fun toFloatArray(targetSamples: Int = maxDurationSamples): FloatArray {
        synchronized(lock) {
            val result = FloatArray(targetSamples)
            val copySize = minOf(buffer.size, targetSamples)
            for (i in 0 until copySize) result[i] = buffer[i]
            return result
        }
    }

    /** 重置缓冲区（用于新的录音会话） */
    fun clear() {
        synchronized(lock) { buffer.clear() }
    }
}
```

```kotlin
// domain/asr/AsrEngine.kt (修改后)

interface AsrEngine {

    // ─── 现有 API（保留，向后兼容） ───

    interface Callback {
        fun onResult(text: String)
        fun onProgress(progress: Float)
        fun onError(error: String)

        fun onPartialResult(refined: RefinedResult)
        /** 最终识别结果（finish() 后的完整转写，已完全稳定） */
        fun onFinalResult(text: String)
        /** 识别出错 */
        fun onError(error: String)
    }

    /**
     * 启动一个流式识别会话。
     * 调用方通过 [StreamingAsrSession.feedAudio] 持续喂入音频，
     * 引擎周期性触发识别并通过 [StreamingCallback.onPartialResult] 回传渐进式结果。
     */
    fun startStreaming(callback: StreamingCallback): StreamingAsrSession
}
```

#### 4.3.3 ResultRefiner — 渐进式结果纠错引擎

```kotlin
// domain/asr/ResultRefiner.kt (新文件)

/**
 * 渐进式识别结果纠错引擎。
 *
 * 核心思路：
 * 每次周期识别的输入是"当前累积的全部音频"，Whisper 在更多上下文下
 * 会自动纠正早期的错误。Refiner 通过对比连续两次的识别结果，
 * 提取稳定前缀和变化后缀，让 UI 可以分层次展示。
 *
 * 纠错场景：
 * 1. 追加（最常见）：前次 "今天天气" → 本次 "今天天气很好"
 *    → stablePrefix="今天天气", newSuffix="很好"
 *
 * 2. 纠正（短音频→长音频）：前次 "金色" → 本次 "今天天气"
 *    → stablePrefix="" (全变了), newSuffix="今天天气" (整体替换)
 *
 * 3. 稳定（上下文足够）：前次 "今天天气很好" → 本次 "今天天气很好"
 *    → stablePrefix="今天天气很好", newSuffix="", isStable=true
 *
 * 4. 重复/幻觉消除：前次 "今天天气。今天天气" → 本次 "今天天气很好"
 *    → stablePrefix="今天天气", newSuffix="很好" (Whisper 修正了重复)
 *
 * 算法：最长公共前缀 (Longest Common Prefix)
 * - 从前往后逐字比较，找到第一个不同的位置
 * - 该位置之前 = stablePrefix
 * - 该位置及之后的新内容 = newSuffix
 *
 * 注：这里使用字符级比较而非 token 级，因为 Whisper BPE tokenizer 的
 * token 边界不稳定，字符级更直观且足以满足 UI 展示需求。
 */
class ResultRefiner {

    /** 上一次的完整识别文本 */
    private var previousText: String = ""

    /**
     * 对新的识别结果进行纠错处理。
     *
     * @param currentText 本次周期识别的完整文本
     * @return RefinedResult 包含稳定前缀和变化后缀
     */
    fun refine(currentText: String): AsrEngine.RefinedResult {
        if (previousText.isEmpty()) {
            previousText = currentText
            return AsrEngine.RefinedResult(
                fullText = currentText,
                stablePrefix = "",
                newSuffix = currentText,
                isStable = false,
                stablePrefixLength = 0
            )
        }

        // 计算最长公共前缀长度
        val commonLen = longestCommonPrefix(previousText, currentText)

        val isStable = previousText == currentText
        val stablePrefix = if (commonLen > 0) currentText.substring(0, commonLen) else ""
        val newSuffix = currentText.substring(commonLen)

        previousText = currentText

        return AsrEngine.RefinedResult(
            fullText = currentText,
            stablePrefix = stablePrefix,
            newSuffix = newSuffix,
            isStable = isStable,
            stablePrefixLength = commonLen
        )
    }

    /** 重置状态（新录音会话开始时调用） */
    fun reset() {
        previousText = ""
    }

    /**
     * 计算两个字符串的最长公共前缀长度（Unicode 字符级别）。
     */
    private fun longestCommonPrefix(a: String, b: String): Int {
        val minLen = minOf(a.length, b.length)
        for (i in 0 until minLen) {
            if (a[i] != b[i]) return i
        }
        return minLen
    }
}
```

#### 4.3.4 AsrEngineImpl 流式实现（集成 ResultRefiner）

```kotlin
// domain/asr/AsrEngineImpl.kt (新增部分)

@Singleton
class AsrEngineImpl @Inject constructor(
    private val modelService: ModelServiceFacade,
    private val asrModelManager: AsrModelManager
) : AsrEngine {

    // ... 现有 file-based transcribe 保留不变 ...

    override fun startStreaming(callback: AsrEngine.StreamingCallback): StreamingAsrSession {
        return StreamingAsrSessionImpl(modelService, asrModelManager, callback)
    }
}

/**
 * 流式识别会话实现。
 *
 * 核心策略：
 * 1. AudioBuffer 持续累积音频
 * 2. 每累积 ~2 秒新音频触发一次识别
 * 3. 如果上一次识别还在跑，跳过本次（避免堆积）
 * 4. 每次识别结果通过 ResultRefiner 对比上次结果，产出稳定/变化标记
 * 5. finish() 时运行最后一次完整识别
 */
class StreamingAsrSessionImpl(
    private val modelService: ModelServiceFacade,
    private val asrModelManager: AsrModelManager,
    private val callback: AsrEngine.StreamingCallback
) : StreamingAsrSession {

    private val audioBuffer = AudioBuffer()
    private val refiner = ResultRefiner()              // ← 新增：渐进式纠错
    private val recognitionIntervalMs = 2000L           // 每 2 秒触发一次识别
    private val minAudioForRecognition = 16000          // 至少 1 秒音频才开始识别

    private val scope = CoroutineScope(Dispatchers.IO + SupervisorJob())
    private var lastRecognitionTime = 0L
    private var running = AtomicBoolean(false)
    private var cancelled = AtomicBoolean(false)

    private val _isRunning = AtomicBoolean(false)
    override val isRunning: Boolean get() = _isRunning.get()

    override fun feedAudio(chunk: FloatArray) {
        if (cancelled.get()) return
        audioBuffer.append(chunk)

        val now = System.currentTimeMillis()
        val hasEnoughAudio = audioBuffer.sampleCount >= minAudioForRecognition
        val hasEnoughInterval = now - lastRecognitionTime >= recognitionIntervalMs
        val notAlreadyRunning = !running.get()

        if (hasEnoughAudio && hasEnoughInterval && notAlreadyRunning) {
            triggerRecognition(isFinal = false)
        }
    }

    override fun finish() {
        if (cancelled.get()) return

        // 取消可能正在跑的中间识别，以最终识别为准
        running.set(false)

        // 等待一小段确保线程安全，然后跑最终识别
        scope.launch {
            delay(100)
            triggerRecognition(isFinal = true)
        }
    }

    override fun cancel() {
        cancelled.set(true)
        running.set(false)
        audioBuffer.clear()
        refiner.reset()
    }

    private fun triggerRecognition(isFinal: Boolean) {
        if (cancelled.get()) return
        running.set(true)
        _isRunning.set(true)
        lastRecognitionTime = System.currentTimeMillis()

        scope.launch {
            try {
                val audioData = audioBuffer.toFloatArray()
                if (!asrModelManager.isModelReady()) {
                    callback.onError("ASR 模型未就绪")
                    return@launch
                }

                modelService.bind()
                modelService.loadAsr(asrModelManager.getModelDir())

                val result = modelService.transcribeAudioData(audioData)

                result.fold(
                    onSuccess = { text ->
                        if (isFinal) {
                            callback.onFinalResult(text)
                        } else {
                            // ─── 渐进式纠错处理 ───
                            val refined = refiner.refine(text)
                            callback.onPartialResult(refined)
                        }
                    },
                    onFailure = { e ->
                        callback.onError(e.message ?: "转写失败")
                    }
                )
            } catch (e: Exception) {
                if (!cancelled.get()) {
                    callback.onError("转写出错: ${e.message}")
                }
            } finally {
                running.set(false)
                _isRunning.set(false)
            }
        }
    }
}
```

```kotlin
    audioRecorder.setChunkListener(null)

    if (file == null || durationMs <= 0) {
        _uiState.value = _uiState.value.copy(isRecording = false)
        return

    _uiState.value = _uiState.value.copy(isRecording = false, isTranscribing = true)

    // ─── 先结束流式会话，获取最终结果 ───
    streamingSession?.finish()

    viewModelScope.launch {
        // 等待流式识别最终结果（最多 5 秒）
        var finalText = accumulatedFinalText
        if (finalText.isBlank()) {
            withTimeoutOrNull(5000) {
                while (accumulatedFinalText.isBlank() && _uiState.value.isStreamingRecognition) {
                    delay(200)
                }
                finalText = accumulatedFinalText
            }
        }

        // 如果流式识别完全失败，回退到完整文件转写
        if (finalText.isBlank()) {
            finalText = transcribeFileFallback(file)
        }

        // 后续的润色逻辑不变
        if (finalText.isNotBlank()) {
            val block = repository.addVoiceBlock(noteId, file, durationMs)
            repository.updateTranscription(block.id, finalText)
            // Polish...
        }

        _uiState.value = _uiState.value.copy(
            isTranscribing = false,
            liveCaption = "",
            liveCaptionStableLen = 0
        )
    }
}

private suspend fun transcribeFileFallback(file: File): String {
    return withContext(Dispatchers.IO) {
        val signal = CompletableDeferred<String>()
        asrEngine.transcribe(file, object : AsrEngine.Callback {
            override fun onResult(text: String) { signal.complete(text) }
            override fun onProgress(progress: Float) {}
            override fun onError(error: String) { signal.complete("") }
        })
        signal.await()
    }
}
```

### 4.6 关键设计决策

#### 4.6.1 识别触发间隔：2 秒

| 间隔 | 延迟感 | CPU 占用 | 选择 |
|------|--------|---------|------|
| 500ms | 低 | 高（识别跑不完就堆积） | ❌ |
| **2s** | **可接受** | **适中** | ✅ |
| 5s | 明显等待 | 低 | ❌ |

Whisper tiny 在手机上推理一次需要 2~4 秒。2 秒的触发间隔配合"跳过正在运行的识别"策略，实际触发间隔在 2~4 秒之间，用户感知为"字幕每几秒刷新一次"。

#### 4.6.2 最小识别音频量：1 秒

少于 1 秒的音频信息量太少，Whisper 容易产生幻觉输出。设置 16000 samples（1 秒）为最小阈值。

#### 4.6.3 并发策略：跳过而非排队

当上一次识别还在运行时，新的音频块到达不排队新的识别任务，而是直接跳过。理由：
- Whisper 推理是 CPU 密集型，并行推理会让手机发烫且两个推理都变慢
- 排队会导致结果延迟越来越长（"雪崩效应"）
- 跳过的下一次触发会拿到更多累积音频，结果质量更好

#### 4.6.4 finish() 策略：取最新 + 回退

```
finish() 调用时：
  1. 如果有流式识别正在运行 → 等待它完成 → 取其结果为 final
  2. 如果没有 → 立即触发一次完整识别 → 取其结果为 final
  3. 如果流式结果为空/失败 → 回退到完整文件转写（现有路径）
```

#### 4.6.5 音频数据传输优化

流式场景中，音频数据不再通过文件路径传递，而是直接在 AIDL 中传递 FloatArray：
- 省去文件 I/O 的写入+读取
- 省去 WAV 格式的编解码
- 2 秒音频在 AIDL 中传输量：32000 floats × 4 bytes = 128 KB，Binder 完全承受得住

#### 4.6.6 渐进式结果纠错策略

见 [4.3.3 ResultRefiner](#433-resultrefiner--渐进式结果纠错引擎)，核心设计要点：

| 决策点 | 选择 | 理由 |
|--------|------|------|
| 纠错算法 | 最长公共前缀 (LCP) | 简单可靠，O(n) 复杂度，覆盖追加/纠正/幻觉消除 |
| 比较粒度 | Unicode 字符 | BPE token 边界不稳定，字符级更直观 |
| 纠错时机 | 每次周期识别完成后 | 实时性最佳 |
| 纠错范围 | 全文对比（非仅后缀） | 必须处理 Whisper 修正早期文字的场景 |
| 失败处理 | 不额外处理 | 回退到完整文件转写已有兜底 |
| UI 呈现 | 稳定前缀正常显示 + 变化后缀高亮 | 用户一眼分辨"已确认"和"可能变" |

## 5. 模型网络分发方案

### 5.1 当前问题

模型文件（Whisper tiny 三文件）约 180MB，当前通过两种方式获取：

1. **APK assets 内置**：模型随 APK 打包，`AsrModelManager.prepareFromAssets()` 首次启动时从 assets 复制到内部存储
2. **Gradle task 下载**：构建时通过 `downloadAllModels` task 下载到 assets 目录

**痛点**：
- APK 体积从 ~15MB 膨胀到 ~200MB，显著降低下载转化率
- 用户可能从不使用语音功能，却被强制下载模型
- 模型更新（如从 tiny 升级到 base）需要发新版 APK
- Google Play 的 200MB APK 限制：接近上限，后续加 LLM 模型（~1GB）完全不可行

#### 5.2.2 ModelDownloadManager 设计

```kotlin
// domain/model/ModelDownloadManager.kt (新文件)

/**
 * 模型文件网络下载管理器。
 *
 * 特性：
 * - 断点续传（HTTP Range 请求）
 * - SHA-256 校验
 * - 下载进度 Flow
 * - WiFi-only 选项
 * - 多文件顺序下载
 */
@Singleton
class ModelDownloadManager @Inject constructor(
    @ApplicationContext private val context: Context
) {

    companion object {
        private const val TAG = "ModelDownloadMgr"

        // 模型文件清单及其远端 URL
        data class ModelFileInfo(
            val filename: String,
            val url: String,
            val sha256: String,
            val sizeBytes: Long
        )

        // TODO: 替换为实际 CDN URL
        private const val CDN_BASE_URL = "https://cdn.speakin.app/models/whisper-tiny/v1"

        val MODEL_FILES = listOf(
            ModelFileInfo(
                filename = "whisper_pre_enc.pte",
                url = "$CDN_BASE_URL/whisper_pre_enc.pte",
                sha256 = "abc123...",  // 构建时由 Gradle 脚本注入
                sizeBytes = 120_000_000
            ),
            ModelFileInfo(
                filename = "whisper_decoder.pte",
                url = "$CDN_BASE_URL/whisper_decoder.pte",
                sha256 = "def456...",
                sizeBytes = 55_000_000
            ),
            ModelFileInfo(
                filename = "tokenizer.json",
                url = "$CDN_BASE_URL/tokenizer.json",
                sha256 = "ghi789...",
                sizeBytes = 3_000_000
            )
        )
    }

    private val _downloadState = MutableStateFlow<DownloadState>(DownloadState.Idle)
    val downloadState: StateFlow<DownloadState> = _downloadState.asStateFlow()

    sealed class DownloadState {
        /** 空闲/未开始 */
        data object Idle : DownloadState()
        /** 正在下载 */
        data class Downloading(
            val currentFile: String,
            val fileIndex: Int,
            val totalFiles: Int,
            val fileProgress: Float,     // 0.0 ~ 1.0
            val totalProgress: Float,    // 0.0 ~ 1.0（按字节加权）
            val downloadedBytes: Long,
            val totalBytes: Long
        ) : DownloadState()
        /** 下载完成并通过校验 */
        data object Completed : DownloadState()
        /** 下载失败 */
        data class Failed(val error: String) : DownloadState()
    }

    /**
     * 获取模型存放目录。
     */
    fun getModelDir(): File = File(context.filesDir, "models/whisper")

    /**
     * 检查模型是否已就绪。
     */
    fun isModelReady(): Boolean {
        val dir = getModelDir()
        return MODEL_FILES.all { info ->
            val file = File(dir, info.filename)
            file.exists() && file.length() >= info.sizeBytes * 0.95  // 允许 5% 误差
        }
    }

    /**
     * 开始下载所有模型文件。
     *
     * @param wifiOnly 是否仅在 WiFi 下下载
     * @return 是否成功触发下载
     */
    suspend fun startDownload(wifiOnly: Boolean = true): Boolean {
        if (wifiOnly && !isWifiConnected()) {
            _downloadState.value = DownloadState.Failed("需要 WiFi 连接")
            return false
        }

        val dir = getModelDir()
        dir.mkdirs()

        var totalDownloaded = 0L
        val totalSize = MODEL_FILES.sumOf { it.sizeBytes }

        for ((index, info) in MODEL_FILES.withIndex()) {
            val destFile = File(dir, info.filename)

            // 已存在且大小正确则跳过
            if (destFile.exists() && destFile.length() >= info.sizeBytes * 0.95) {
                totalDownloaded += info.sizeBytes
                continue
            }

            _downloadState.value = DownloadState.Downloading(
                currentFile = info.filename,
                fileIndex = index,
                totalFiles = MODEL_FILES.size,
                fileProgress = 0f,
                totalProgress = totalDownloaded.toFloat() / totalSize,
                downloadedBytes = totalDownloaded,
                totalBytes = totalSize
            )

            try {
                downloadSingleFile(info, destFile) { fileProgress ->
                    val currentFileBytes = (info.sizeBytes * fileProgress).toLong()
                    _downloadState.value = DownloadState.Downloading(
                        currentFile = info.filename,
                        fileIndex = index,
                        totalFiles = MODEL_FILES.size,
                        fileProgress = fileProgress,
                        totalProgress = (totalDownloaded + currentFileBytes).toFloat() / totalSize,
                        downloadedBytes = totalDownloaded + currentFileBytes,
                        totalBytes = totalSize
                    )
                }

                // 校验 SHA-256
                if (!verifyChecksum(destFile, info.sha256)) {
                    destFile.delete()
                    _downloadState.value = DownloadState.Failed("${info.filename} 校验失败，请重试")
                    return false
                }

                totalDownloaded += info.sizeBytes
            } catch (e: Exception) {
                Log.e(TAG, "Download failed: ${info.filename}", e)
                _downloadState.value = DownloadState.Failed("下载失败: ${e.message}")
                return false
            }
        }

        _downloadState.value = DownloadState.Completed
        return true
    }

    /**
     * 单文件下载（支持断点续传）。
     */
    private suspend fun downloadSingleFile(
        info: ModelFileInfo,
        dest: File,
        onProgress: (Float) -> Unit
    ) = withContext(Dispatchers.IO) {
        val existingSize = if (dest.exists()) dest.length() else 0L

        val connection = URL(info.url).openConnection() as HttpURLConnection
        connection.connectTimeout = 30_000
        connection.readTimeout = 120_000

        if (existingSize > 0 && existingSize < info.sizeBytes) {
            // 断点续传
            connection.setRequestProperty("Range", "bytes=$existingSize-")
        }

        connection.connect()

        val responseCode = connection.responseCode
        val inputStream = if (responseCode in 200..299 || responseCode == 206) {
            connection.inputStream
        } else {
            throw IOException("HTTP $responseCode")
        }

        val outputStream = FileOutputStream(dest, existingSize > 0)
        val buffer = ByteArray(8192)
        var downloaded = existingSize
        var bytesRead: Int

        while (inputStream.read(buffer).also { bytesRead = it } != -1) {
            outputStream.write(buffer, 0, bytesRead)
            downloaded += bytesRead
            onProgress(downloaded.toFloat() / info.sizeBytes)
        }

        outputStream.flush()
        outputStream.close()
        inputStream.close()
        connection.disconnect()
    }

    /**
     * 校验文件 SHA-256。
     */
    private fun verifyChecksum(file: File, expectedSha256: String): Boolean {
        if (expectedSha256.isBlank()) {
            Log.w(TAG, "No checksum provided for ${file.name}, skipping verification")
            return true
        }
        val digest = MessageDigest.getInstance("SHA-256")
        FileInputStream(file).use { fis ->
            val buffer = ByteArray(8192)
            var bytesRead: Int
            while (fis.read(buffer).also { bytesRead = it } != -1) {
                digest.update(buffer, 0, bytesRead)
            }
        }
        val actual = digest.digest().joinToString("") { "%02x".format(it) }
        val matches = actual.equals(expectedSha256, ignoreCase = true)
        if (!matches) {
            Log.e(TAG, "Checksum mismatch for ${file.name}: expected=$expectedSha256, actual=$actual")
        }
        return matches
    }

    private fun isWifiConnected(): Boolean {
        val cm = context.getSystemService(Context.CONNECTIVITY_SERVICE) as ConnectivityManager
        val network = cm.activeNetwork ?: return false
        val caps = cm.getNetworkCapabilities(network) ?: return false
        return caps.hasTransport(NetworkCapabilities.TRANSPORT_WIFI)
    }
}
```

## 7. 风险与缓解

| 风险 | 概率 | 影响 | 缓解措施 |
|------|------|------|---------|
| **Whisper tiny 推理太慢**，导致流式结果滞后严重 | 中 | 用户体验差 | 先用 tiny 模型（最快）；后续考虑换 base 模型或量化优化 |
| **AIDL 传大 FloatArray 触发 TransactionTooLarge** | 低 | 流式识别崩溃 | 2s 音频 = 128KB，远低于 1MB Binder 限制；30s 音频 = 1.9MB，改用共享内存 |
| **频繁推理导致手机发热/耗电** | 中 | 用户投诉 | 限制最大识别频率（2s 间隔 + 跳过排队）；监控 CPU 温度 |
| **部分识别结果质量差**（短音频上下文不足） | 中 | 用户对 live caption 失去信任 | UI 上标注"实时预览"；录音结束后用完整音频做最终转写替换；**通过 ResultRefiner 的稳定/变化标记让用户区分可信度** |
| **渐进式纠错显示闪烁**（频繁变化导致 UI 抖动） | 中 | 视觉体验差 | 控制识别频率（≥2s）；稳定前缀与变化后缀用不同样式区分，不做整行替换动画 |
| **与现有文件转写路径冲突** | 低 | 功能回归 | 保留完整的旧路径作为回退方案；充分回归测试 |
| **CDN 下载失败率高**（网络环境差） | 中 | 用户无法使用 ASR | 断点续传；WiFi-only 选项；保留旧版 assets 路径兼容升级用户 |
| **模型下载中途退出** | 中 | 下次启动需重新开始 | 断点续传（HTTP Range）；已完成的文件不重复下载 |
| **模型版本不兼容**（远端更新后与旧 App 不兼容） | 低 | 转写失败 | 版本号管理；manifest.json 声明兼容 App 版本范围 |
| **CDN 带宽成本过高** | 低 | 运营成本超标 | 用量监控 + 预算告警；可考虑 P2P 分发或按需下载 |
| **存储空间不足** | 中 | 下载失败 | 下载前检查可用空间（需 ≥ 模型大小 × 1.5）；提示用户清理 |

## 8. 后续演进方向

### 8.1 短期（v1.1）：VAD 语音活动检测

在 AudioBuffer 前端加入 VAD：
- 只对有语音的片段触发识别
- 自动切分句子（基于静音间隔）
- 减少无效推理，降低功耗
- **与渐进式纠错配合**：VAD 切分后的片段，前后文相关性降低，Refiner 可重置状态避免跨句纠错

### 8.2 短期（v1.1）：更智能的渐进式纠错

当前 ResultRefiner 使用 LCP（最长公共前缀），可进一步优化：

```
v1.1 改进方向：
- 编辑距离 (Levenshtein Distance)：处理中间插入/删除场景
  "我今天吃饭" → "我今天去吃饭了" → 变化点在第 3 个字位置
- 多结果投票：连续 N 次识别中对同一位置的字做多数表决
- 置信度估计：Whisper decoder logits 可输出每个 token 的置信度，
  低于阈值的 token 在 UI 上标灰/下划线
- 语义完整性检测：避免在词语/短语中间截断（在标点或语义边界处显示稳定标记）
```

### 8.3 中期（v1.2）：Encoder 输出缓存

```
第一次识别: [音频 0-2s 补零到 30s] → Encoder → Decoder → 文本
第二次识别: [音频 0-3s 补零到 30s] → Encoder → Decoder → 文本
                                       ↑ 前面 2s 的编码重复计算了！
```

优化方案：
- 缓存已编码的音频段的 encoder output
- 只编码新增部分，拼接 encoder outputs
- 注：Whisper 使用绝对位置编码，拼接需谨慎处理（分段编码 + 位置偏移）

### 8.4 中期（v1.3）：模型多版本管理

- 支持同时安装多个模型（tiny / base / small）
- 用户可按需切换（精度优先 vs 速度优先）
- 模型间共享 tokenizer.json
- 存储空间管理：自动清理最久未使用的模型

### 8.5 长期（v2.0）：替换为真正的流式模型

当需要**逐字实时**级别的体验时，替换为流式 ASR 模型：

| 候选模型 | 推理框架 | 模型大小 | 流式能力 |
|---------|---------|---------|---------|
| SenseVoice-Small | ONNX Runtime | ~80MB | ✅ 原生流式 |
| Paraformer-large | FunASR / ONNX | ~200MB | ✅ 原生流式 |
| Whisper-streaming | ExecuTorch | ~75MB | ✅ 需要 adapter |

依托 `AsrEngine` 接口的抽象，替换模型只需：
1. 实现新的 `AsrEngine`（如 `SenseVoiceEngine`）
2. 修改 DI 绑定
3. UI 层零改动（`ResultRefiner` 仍然适用）
